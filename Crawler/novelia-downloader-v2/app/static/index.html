    Pacing

    How quickly requests are sent. Applies to running tasks when they next start or resume.

    Preset

    Fills the pacing and backoff fields below. Use Gentle for long sweeps or after being refused.

    Delay between requests

    Minimum gap between any two requests, shared by every task and the catalog browser.

    Random variation

    Varies each delay by up to this much so requests do not arrive on a fixed beat.

    Slow down when refused

    Each rate-limit response doubles the extra delay; it shrinks again after successful requests.

    Slowest delay

    Upper limit for the adaptive delay.

    What happens when a request fails or the site starts refusing.

    Attempts per request

    For network errors, server errors and interrupted transfers.

    First backoff

    Wait after the first failure or HTTP 429; doubles each time, with random variation. A longer Retry-After from the site always wins.

    Longest backoff
    Keep trying for

    How long one request keeps backing off while rate limited before the task pauses.

    Then pause the task for

    The task returns to the queue and resumes by itself. Other queued tasks may run meanwhile.

    Pauses in a row

    Give up after this many pauses without any successful item. 0 stops at the first pause.

    Automatic retry rounds

    At the end of a task, temporarily failed items are tried again. Permanent errors such as 404 are left for you.

    Wait before a round

    Multiplied by the round number: 1×, 2×, 3×…

    Pause after network failures

    When this many items in a row fail because the connection is down, they go back in the queue and the task pauses instead of failing everything after them. 0 never pauses.
